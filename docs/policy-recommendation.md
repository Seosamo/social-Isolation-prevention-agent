# 탐지 근거와 연결한 정책 검색·추천

## 결과를 관찰하고 재계획하는 Agent

자동 추천의 진입점은 `policies.agent.search_policies`입니다. 최초 검색 결과를 평가한 뒤
vLLM이 다음 탐색 도구 또는 종료를 선택합니다. `local_services`는 연도·인구 검색어를
줄여 지역 서비스·복지관·주민센터 경로를 찾고, `national_programs`는 전국 제도를 찾으며,
`evidence_support`는 검증된 탐지와 연결된 지원 목적을 탐색합니다. 마지막 행동은 탐지 가설이
있을 때만 허용합니다. 검색어에서 조건을 생략하더라도 원문의 지역·연령·성별 자격 검사는 유지합니다.
시도를 진행하면서 모은 모든 후보를 합쳐 중복 제거·조건 충돌 검사·순위 산정을 다시 수행합니다.

모델에는 후보 수, 목적 일치 수, 지역 후보 수, 접수 확인 수, 시군 선택지 수, 제외·오류 종류,
탐지 지원 목적 ID와 현재 허용된 행동을 전달합니다. 행동과 사유 코드를 JSON으로 받아
허용 목록과 재시도 여부를 검사합니다. 임의 검색어·URL·명령 실행은 허용하지 않습니다.
모델의 내부 사고 과정 대신 관측값, 실제 도구, 선택 행동, 사유 코드, 결정 주체를 기록합니다.
모델이 정한 `stop` 또는 시간·횟수 제한, 지역 미지정, 검색 키 누락에서 종료합니다.

기본값은 최대 3회 탐색(최초 검색 포함), 전체 60초, 회차별 최대 20초입니다.
최초 최대 4개 검색 후 재탐색은 전략별 최대 2개 검색입니다. 하드 한도는 검색 10회·원문
16개이며, 매 회차 원문 선택은 최대 8개입니다. 동일 요청에서 확인한 URL은 재수집·재추출하지
않습니다. vLLM 행동 판단은 호출당 최대 4초이며 최종 목적 재평가는 모은 후보 전체에서 한 번만
수행합니다. 이 예산은 정책 탐색 부분에 적용하며, 질문 해석·최종 답변 생성 시간은 별도입니다.

`local` 모드도 같은 루프를 사용하되 정해진 규칙으로 다음 전략을 선택합니다. vLLM의
JSON·행동 검증 실패나 서버 오류 시에도 규칙 결정으로 계속하며 기록에 `rule_fallback`을
남깁니다. 후보가 없다는 이유로 자격 검사를 풀거나 과거 정책으로 현재 추천을 채우지 않습니다.
`policies.agent_loop=false`로 기존 단일 탐색으로 복귀할 수 있습니다.

### 다른 환경에서 실제 vLLM 확인

PowerShell에서 `TAVILY_API_KEY`, `VLLM_BASE_URL`, `VLLM_MODEL` 환경변수를 설정합니다.
`.env`는 자동 로드하지 않습니다. 서버의 실제 모델 이름을 사용한 뒤 다음을 실행합니다.

```powershell
python -m activity_agent llm-check
python -m activity_agent ask --task isolation --backend vllm "2025년 12월 강원 50대 남성 활동 위축 근거와 고립 예방 정책 추천"
```

결과는 설정된 출력 폴더의 `policies/lookups/*.json`에 저장됩니다. `agent.steps`에서
`decision.method=vllm`인지, `observation` 이후 서로 다른 `tool`이 호출됐는지,
`agent.stop_reason`과 `tool_calls`가 예산 안인지 확인합니다. 첫 탐색이 충분하면 모델이
바로 종료해도 정상입니다. `rule_fallback`이면 모델 생성·JSON 응답을 점검합니다.
`tests/test_policy_agent.py`는 실제 네트워크와 모델 없이 재계획·종료·잘못된 행동·자격 유지·
중복 조회 방지·시간 제한을 검사합니다. 이 테스트는 실제 모델의 검색 판단 품질을 보장하지 않습니다.

## 처리 흐름

질문 조건과 검증된 탐지 관측을 분리하여 저장합니다. 활동 감소를 관계망·지역 활동 참여, 기존 `persistent_20pct`를 안부 확인·지속적 관계 지원의 탐색 가설로 연결합니다. 탐지 백분위와 감소율을 정책 적합도 점수로 바꾸지 않습니다. 지역 공통 낮·주말 변화나 소비 변화만으로 개인의 지원 필요를 추정하지 않습니다.

탐지 관측은 이미 답변에 사용하는 후보 표본에서 가져옵니다. IF_F2는 `candidate`와 `quality_eligible`이 참이며 감소율이 유효한 행, 활동 에이전트는 품질이 `ok`이고 점수가 유효한 집단 유동 감소 행만 사용합니다. 후보가 없거나 평가 불가이면 사용자 조건만 사용합니다. 동일 지역·연령·성별의 목적을 묶어 한 답변 안에서는 같은 탐색 결과를 재사용하고, 후보가 부족할 때만 다른 전략으로 검색합니다. 정책 대상 조건이 관측 집단과 맞는 경우에만 해당 근거 ID를 연결합니다.

검색 API에는 지역·집단 조건·목적만 전달합니다. 근거 ID·소지역 코드·점수·감소율은 검색어에 넣지 않습니다. 내부 관측과 원문은 설정된 vLLM 서버에 전달될 수 있습니다.

## 문서 발견과 근거 선택

검색은 지역의 구체 조건 검색, 인구 조건을 넓힌 지역 서비스 검색, 전국 제도·신청 안내 검색 두 가지로 구성합니다. 지역 검색은 해당 지역 공식 도메인에, 전국 검색은 중앙정부·공식 복지 도메인에 한정하여 서로 결과를 잠식하지 않게 합니다. 사용자가 지정한 목적을 우선하고 탐지 기반 목적은 보완 검색에 사용합니다. 인구 조건을 넓혀 발견한 결과도 원문에서 연령·성별·지역을 다시 검증합니다. 각 검색의 원래 순위를 보존하여 `sum(1 / (60 + rank))`로 URL별 결과를 통합합니다. 동일 검색 안에서 반복된 게시물은 점수를 중복 가산하지 않습니다.

원문 확인은 검색어별 최상위 고유 문서를 먼저 배정한 뒤 통합 순위로 채웁니다. 단일 탐색 함수의 한도는 검색 4회·검색당 5개·공식 원문 8개·추천 3개·전체 30초이며, Agent 경유 시에는 위의 공유 예산을 적용합니다. URL의 추적 인자만 제거하고 게시물·연도·차수 식별 인자는 보존합니다. 게시물 ID가 명확한 경우에만 메뉴·페이지 등 알려진 표시 인자를 무시합니다.

실제 Tavily 요청은 최대 4개 병렬 실행하고 검색 단계 예산은 최대 12초로 제한합니다. 개별 원문 요청은 기본 6초입니다. PDF·HWP·다운로드·목록·태그·기본계획 등은 원문 확인 한도 전에 분리합니다. 보건복지부의 `list_no`, 서울 1인가구포털의 `partcptn_id` 등 게시물 ID를 인식해 메뉴·페이지가 다른 같은 공고를 반복 조회하지 않습니다.

`references/policy_service_sources.json`은 정책 결과가 아니라 현재 원문을 확인할 공식 서비스 안내 주소 목록입니다. 해당 목적의 검색에서는 원문 확인 한 자리로 이 안내를 매번 새로 조회합니다. 예상 사업 제목·대상·신청 경로를 확인하지 못하면 추천하지 않습니다. 전국 제도 안내는 거주지별 제공서비스·선정 조건이 확인된 모집 공고와 구분하며 접수 중이라고 단정하지 않습니다. 상수로 저장한 과거 대상·기간을 반환하지 않습니다.

강원도청 같은 사업 목록 표는 헤더와 행·열 병합을 해석해 사업별로 분리합니다. 사업별 대상·내용·신청 경로를 보존하여 한 페이지의 노인 전용 조건이 다른 중장년 사업에 섞이지 않게 합니다. 표 제목만으로 대상·신청 경로가 확인됐다고 판단하지 않습니다. 표 근거에는 행 ID와 `structured_table_row` 표현 방식을 기록합니다.

시군별 사업은 원문 제목의 적용 시군을 반영합니다. 시도만 지정한 경우 해당 사업은 `regional_options`에 구분하고 시군 확인을 요청합니다. 특정 시군을 지정했을 때 다른 시군 사업은 제외합니다. 원문에서 대상·신청 경로를 확보하지 못한 보도자료는 `reference_materials`로 분리해 최종 정책 후보를 채우지 않습니다.

본문은 약 1,800자, 겹침 200자 구간으로 나누고 대상·기간·신청 방법과 지원 목적에 관련된 구간을 문서당 최대 4개 선택합니다. 각 구간에는 공식 URL, 본문 위치, SHA-256, 고유 ID가 있습니다. 자격·기간 검사에는 전체 수집 본문에서 찾은 조건을 사용합니다. 선택 구간에서 추출한 문구가 전체 본문의 기존 조건을 덮어쓰지는 못합니다. 첨부파일만의 조건은 미확인으로 남깁니다.

## 정책 묶음과 순위

사업명·담당기관·적용 지역·사업 연도·모집 차수가 모두 확인되어야 서로 다른 URL을 같은 정책으로 묶습니다. 기관·지역·연도·차수는 일치해야 하며 정규화 사업명의 문자 3개 단위 유사도는 0.9 이상이어야 합니다. 누락된 식별 정보는 추정하지 않습니다. 같은 정책 묶음의 공식 링크와 출처별 조건을 보존합니다.

대표 자료는 모집 공고, 사업 안내, 보도자료 순으로 선택합니다. 대상·기간이 충돌하면 현재 접수 상태를 확정하지 않습니다. 본문에 `정정대상: https://...` 형태로 같은 묶음의 원 공고가 명시된 단일 정정 공고가 있을 때만 그 조건으로 대체합니다. 명확한 마감·자격 불일치 공고는 추천 전에 제외합니다.

모집 상태는 접수 중·상시, 접수 예정, 확인 필요의 세 그룹으로 고정합니다. 그룹 안에서 목적 40%, 적용 지역 25%, 신청 정보 20%, 근거 충실도 15%로 정렬합니다. 사용자 명시 목적 일치를 우선하며, 탐지 목적의 지원 내용 일치는 보조로 사용합니다. 지속 감소 가설에서는 안부 확인 목적의 비중을 높입니다. 게시일·탐지 백분위는 가중치가 아닙니다. 초기 규칙 점수는 운영 기본값이며 수급 가능성이나 정책 효과 확률이 아닙니다.

vLLM 재평가는 상위 6개를 한 번에 최대 5초 동안 처리하고 목적 적합성만 0~3등급으로 평가합니다. 정책 ID·목적 ID·구간 ID·연속 원문 인용과 관련 단어를 검증합니다. 응답 전체가 검증을 통과해야 목적 점수를 반영하며 자격·모집 그룹은 바꾸지 않습니다. 잘못된 출력이나 시간 초과 시 규칙 순위를 그대로 제공합니다. `policies.rerank=false`는 재평가만 끄며 기존 근거 추출·설명 기능과는 별개입니다.

## 응답·기록·실패

기존 정책 필드 외에 `group_id`, `related_sources`, `evidence_chunks`, `purpose_matches`, `linked_evidence_ids`, `ranking`을 제공합니다. `ranking`은 규칙 점수·항목·순위와 최종 점수·항목·순위를 구분하고 버전을 기록합니다. 추천 이유와 탐지 연결은 가설임을 표시하고 미확인 조건을 함께 제시합니다.

`policies/lookups/` 기록에는 검색어별 순위와 선택 문서, 제외 이유, 정책 묶음, 최종 순위와 재평가 상태, 처리 시간이 남습니다. 검색 서비스 오류에는 예외 종류만 기록하여 키·응답 헤더가 남지 않게 합니다. 검색 실패 시 과거 확인 자료를 별도 참고 링크로 표시하며 현재 추천에 섞지 않습니다.

## 검증

`tests/fixtures/policy_ranking_cases.json`의 12개 고정 시나리오에서 기존 정렬과 새 상위 3개 포함률 및 지정 1순위를 비교합니다. 목적·지속 감소·모집 상태·연령·성별·지역·같은 사업의 여러 자료·다른 모집 차수를 포함합니다. 별도 테스트는 문서 뒤쪽 조건, 다른 연도, 원문 충돌·정정, 검색 공정 배분, 식별 쿼리 보존, 재평가 오류·시간 부족과 근거 위조를 검사합니다. 비교 결과는 테스트의 격리된 출력 폴더에 `policies/evaluation.json`으로 저장합니다.

이 평가는 고정 합성 자료의 회귀 검증입니다. 실제 추천 품질과 정책 효과를 증명하지 않습니다. 실검색 점검에는 `TAVILY_API_KEY`가 필요하며 서울·강원 질문 각각에서 공식 링크·기간·적용 지역을 사람이 확인해야 합니다.
